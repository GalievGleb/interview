## P1 — сильно повышает конверсию (закрыть за 2 недели)

- [ ] **Веб-версия бесплатного разбора** (лид-магнит): форма «вставь вакансию → e-mail/Telegram → получи вопросы и риски». Даже если внутри вручную/полуавтоматом через API `apps/api-py`. Это главный крючок воронки: без неё лендинг просит «скачай .exe» холодного человека — это дорого.
- [ ] 3–5 скринов и 1 видео (30–60 сек) реального флоу на лендинг: разбор → карта готовности → overlay. Видео = главный продающий актив, его же в посевы и Shorts.
- [ ] Первые 5 отзывов (даже от бесплатных пользователей Этапа 0 — см. 06-sales-playbook.md) с именем/ролью на лендинг.
- [ ] Экран Billing/Plan в приложении сделать честным: что в моём плане, кнопка «Написать в поддержку для апгрейда» (пока без автоплатежей).
- [ ] E-mail сбор: хотя бы форма «пришлём чек-лист подготовки» (двойная польза: лид-магнит + база для рассылки).

## P2 — до конца месяца 1

- [ ] Продуктовая аналитика внутри приложения (хотя бы события: установка, первый разбор, первая тренировка, первый live) — без этого не посчитать активацию. Учесть privacy-позиционирование: только обезличенные события, с галочкой согласия.
- [ ] Онбординг в приложении: пустое состояние должно вести «вставь вакансию» за ≤ 2 минуты до вау-момента (вероятные вопросы).
- [ ] Триал-механика: Free = 1 разбор (уже так на лендинге) — проверить, что в приложении лимит реально работает и мягко продаёт апгрейд.
- [ ] Автоматизация выдачи доступа после оплаты (вебхук платёжки → ключ). Только когда ручной поток станет узким местом.

## Definition of Done этого файла

Продажи можно запускать, когда: лендинг живёт на домене → CTA ведут в бота → бот принимает вакансию → есть страница оплаты → после оплаты человек получает доступ ≤ 1 часа → Метрика всё это видит.
