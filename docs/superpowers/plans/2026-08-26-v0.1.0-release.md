# SkillCue 0.1.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the user-approved SkillCue dev tree as stable version `0.1.0` through GitHub Releases and the production download path.

**Architecture:** Keep `apps/desktop/package.json` as the release source used by electron-builder, while enforcing the same version across all active workspace packages and the Python backend. A private-repository tag triggers the existing Windows and macOS workflow, which publishes updater assets to the public `GalievGleb/SkillCue` repository; `skill-cue.ru` download routes redirect to that public latest release.

**Tech Stack:** pnpm monorepo, React 19, Electron 39, FastAPI/PyInstaller, Vitest, pytest, ESLint, GitHub Actions, electron-builder.

**Spec:** `docs/superpowers/specs/2026-08-26-v0.1.0-release.md`

## Global Constraints

- Release version and Git tag are exactly `0.1.0` and `v0.1.0`.
- Preserve every current user-approved dev change, including the WAV regression fixture.
- Never print or commit credentials; GitHub authentication comes from the OS credential store.
- Do not deploy unrelated Raspberry Pi code when `apps/api`, `landing`, and server configuration have no diff.
- Do not publish until every required verification gate is fresh and green.

### Task 4: Commit, tag, and publish

**Files:**
- Commit: all intended tracked and untracked files listed by `git status`
- Exclude: credentials, caches, build output, and local application data

**Interfaces:**
- Consumes: fully verified stable release tree.
- Produces: private code commit on `main`, tag `v0.1.0`, and public updater assets.

- [ ] **Step 1: Audit the staged tree**

Run `git status --short`, `git diff --check`, inspect staged file names and size,
and confirm no credential or generated release files are staged.

- [ ] **Step 2: Commit and push main**

Commit the complete release tree with `chore(release): v0.1.0`, then push
`main` to `origin` without force.

- [ ] **Step 3: Create and push the annotated tag**

Create `v0.1.0` on the verified commit and push only that tag to `origin`.

- [ ] **Step 4: Wait for GitHub Actions**

Watch the tag-triggered release workflow until the Windows job and both ordered
macOS jobs finish successfully.
