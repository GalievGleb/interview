Вопросы на собеседовании системного аналитика: 16 вопросов с разбором

Системного аналитика проверяют по четырём осям: требования, интеграции (REST/очереди), моделирование и SQL. Ниже — типовые вопросы каждой оси и что за ними стоит.

Требования

1. Функциональные vs нефункциональные требования?

Что делает система vs какой она должна быть (производительность, безопасность, отказоустойчивость). Пример обоих для одной фичи — сильный ход.

2. User story vs use case — когда что?

Story — формула ценности с критериями приёмки; use case — детальный сценарий с альтернативными потоками. Хотят критерий выбора, а не определения.

3. Какими должны быть хорошие критерии приёмки?

Проверяемые, однозначные, покрывают негатив; формат Given/When/Then. Напишите AC для «восстановления пароля» — частое практическое задание.

4. Заказчик не знает, чего хочет. Что делаете?

Интервью от проблем, прототипы, наблюдение за процессом, короткие итерации. Проверяют процесс, а не «волшебный вопрос».

5. Как управляете изменениями требований в середине разработки?

Фиксация базлайна, оценка влияния, приоритизация с PO, прозрачная коммуникация команде. Хотят зрелость: изменения — норма, хаос — нет.

Интеграции и API

6. Что такое REST? Методы, статус-коды, идемпотентность.

Ресурсы + HTTP-методы + JSON, stateless; GET/PUT/DELETE идемпотентны, POST — нет. База профессии — отвечать без пауз.

7. Как опишете API-контракт для разработчиков?

Эндпоинт, метод, параметры, схемы запроса/ответа, ошибки, примеры; OpenAPI/Swagger. Плюс — версионирование и обратная совместимость.

8. Синхронная vs асинхронная интеграция? Зачем очереди (Kafka/RabbitMQ)?

Развязка по времени и нагрузке, буферизация пиков, гарантии доставки; новые проблемы: порядок, дубли, идемпотентность потребителя. Это вопрос-водораздел между джуном и мидлом.

9. JSON vs XML; где сегодня встречается XML?

JSON — веб и мобайл; XML — банки, госсистемы, SOAP-легаси. Достаточно уверенного практического ответа.

Моделирование

10. Какие диаграммы UML используете и для чего?

Sequence — взаимодействие систем во времени, activity — логика процесса, компонентная — ландшафт. 2–3 диаграммы с целью лучше, чем список из 14.

11. BPMN vs UML activity — в чём разница подходов?

BPMN — бизнес-процессы с ролями/шлюзами, понятен бизнесу; activity — техническая логика. Хотят: для какой аудитории какая нотация.

12. Смоделируйте процесс «оформление заказа» — какие сущности и связи?

Заказ, позиция, товар, клиент, оплата, доставка; связи 1:N, статусная модель заказа. Практика в реальном времени — тренируйте на 2–3 доменах.

SQL и данные

13. JOIN'ы: INNER vs LEFT; когда какой?

INNER — только совпадения, LEFT — вся левая таблица. Готовьтесь писать запрос руками.

14. Что такое нормализация? Когда денормализуют?

Устранение дублирования (1–3НФ); денормализация — для скорости чтения/отчётов. Пример trade-off'а решает.

Про вас

15. Расскажите о сложной интеграции из вашего опыта.

Контекст → системы → контракт → подводные камни (форматы, ретраи, идемпотентность) → результат. Детали типа «падали на дублях событий» доказывают реальность опыта.

16. Разработчик говорит, что ваша постановка неполная. Действия?

Разобрать конкретные пробелы, дополнить, вынести урок в шаблон постановки. Проверяют отношение к обратной связи — без обороны.
