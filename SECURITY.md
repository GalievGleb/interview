# SkillCue — модель угроз и защиты

Честная карта: что защищено сейчас, что защищает только от «честных», и что
требует серверной инфраструктуры. Обновляйте при изменении архитектуры.

## Что уже защищено

| Угроза | Защита |
|---|---|
| Кража API-ключей пользователя | Ключи в OS secure storage (keyring/keytar), не в файлах и не в localStorage |
| Чужой сайт/процесс дёргает localhost-API (жжёт токены, читает данные) | Per-run токен: Electron генерирует случайный секрет, передаёт бэкенду через env `SKILLCUE_API_TOKEN`; HTTP — заголовок `X-SkillCue-Token`, WebSocket — query `token`; без совпадения — 401. Активен всегда в упакованном приложении (бэкенд спавнится Electron'ом) |
| Компрометация renderer'а (XSS → системный доступ) | Electron hardening: `contextIsolation`, `sandbox`, без `nodeIntegration`, CSP в проде, `setWindowOpenHandler` deny, навигация только на свои origin'ы |
| Подделка лицензии «на глаз» | Ed25519-подпись: ключ проверяется оффлайн по публичному ключу; payload (email, план, бюджет, срок) изменить без приватного ключа нельзя |
| Перерасход API-бюджета честным пользователем | Серверные (в локальном бэкенде) лимиты: 15 минут live на trial (копится на STT-сокете, режется и посреди сессии), месячный токен-бюджет по тарифу — 402 на всех LLM-эндпоинтах при исчерпании |
| MITM к LLM-провайдерам | Только HTTPS-эндпоинты (OpenAI/OpenRouter); локальный Ollama — 127.0.0.1 |
| Аудио уходит в облако незаметно | STT полностью локальный (Whisper on-device); в облако идёт только текст к LLM |

## Что защищает только от честных (и почему)

Приложение локальное: определённый пользователь контролирует свою машину.

- **Взлом лимитов/лицензии.** `skillcue.db` можно удалить (сброс trial-минут и
  счётчика токенов), бинарь можно пропатчить (вырезать проверку подписи).
  Это неустранимо для чисто локального приложения. Обфускация даёт минуты
  задержки и ложное чувство защищённости — не делаем.
- **Кража наработок (промпты, knowledge packs, глоссарий).** Всё это лежит в
  PyInstaller-бандле и извлекается. Приемлемый риск для MVP; ядро ценности —
  скорость пайплайна и постоянное развитие, а не статические тексты.

## Красная линия: НИКОГДА не вшивать ВАШИ API-ключи в приложение

Модель «подписка 3000₽ с включёнными токенами» на ваших ключах **нельзя**
делать клиентски: ключ извлекается из бинаря за минуты, и его сожгут на
тысячи долларов. Локальные лимиты этого не остановят (см. выше).

**Правильная архитектура (дорожная карта):** тонкий прокси-сервер:

```
Приложение → proxy.skillcue.app (лицензия в заголовке) → OpenRouter (ВАШ ключ живёт только тут)
```

- Прокси проверяет подпись лицензии, ведёт учёт токенов per-license в своей БД,
  режет по бюджету тарифа — лимиты становятся невзламываемыми.
- Ключ приложения = идентификатор аккаунта; отзыв ключа при рефанде/абьюзе.
- До прокси безопасная модель монетизации: **пользователь приносит свой ключ**
  (как сейчас), а лицензия продаёт функциональность (live/оверлей/mock) —
  локальные лимиты защищают пользователя от самого себя, не вас от него.

## Прочее

- **Подпись кода** (SmartScreen): см. PACKAGING.md, `CSC_LINK`/`CSC_KEY_PASSWORD`.
- **Приватный ключ лицензий** `apps/api-py/.license_signing_key` — в .gitignore;
  потеря = невозможность выпускать ключи, утечка = бесплатные лицензии у всех.
  Хранить в менеджере паролей, на машине не оставлять.
- **Webhook продаж** (`tools/license_webhook.py`): проверяет HMAC LemonSqueezy
  constant-time сравнением; секреты только через env.
- **Зависимости**: `pip-audit` / `pnpm audit` перед релизом (в CI пока нет —
  кандидат на добавление).
