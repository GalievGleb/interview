# Changelog

Все заметные изменения SkillCue. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии по [SemVer](https://semver.org/lang/ru/) (правила — `docs/VERSIONING.md`).

## [Unreleased]

## [0.0.40] — 2026-08-22

### Fixed
- Закрытые технические вопросы HH с объективным ответом больше не откатываются на «Свой вариант»: ответы модели с проверенным knowledge-источником разрешены для автоматического заполнения.
- Для сценария «кнопка не нажимается, в консоли нет ошибок — значит ли это баг бэкенда?» добавлен надёжный локальный ответ «Нет» на случай недоступности онлайн-модели.

### Security
- Автоматический режим технических ответов остаётся fail-closed для личного опыта, зарплаты, документов, города, графика, переезда, поведенческих вопросов и prompt injection.

## [0.0.39] — 2026-08-21

### Added
- В истории интервью и в подробном разборе сессии появилась кнопка подготовки диагностического Markdown-отчёта для Telegram.
- Для новых live-сессий сохраняются модель STT, модель LLM, аудиоисточники, таймлайн ошибок/переподключений и реальные задержки STT, первого токена, полного ответа и end-to-end.
- Telegram Desktop получает отчёт через поддерживаемый `-sendpath`; при отсутствии Telegram файл сохраняется в `Документы/SkillCue Reports` и показывается в Проводнике.

### Changed
- Сохранённые ответы сессии теперь возвращают фактическую модель и время генерации; старые сессии формируют сокращённый отчёт с явной пометкой отсутствующих live-таймингов.
- Перед передачей отчёта SkillCue требует описание проблемы и явное согласие на отправку транскрипта.

### Security
- Отчёт включает только выбранную сессию, автоматически скрывает API/лицензионные ключи, Bearer-значения, email и имя пользователя в локальных путях; аудиозапись не прикладывается.

## [0.0.38] — 2026-08-20

### Added
- Фоновая проверка готовности онлайн-ИИ выполняется при запуске SkillCue и за 45 минут до сохранённого собеседования; уведомление появляется только при проблеме, без клиентского debug-интерфейса.
- На первом экране показан единый путь «резюме → HH → оверлей».
- Добавлена выключенная по умолчанию локальная обезличенная диагностика категорий сбоев и счётчиков; данные попадают только в архив, который пользователь собирает вручную.

### Changed
- Страница успешной оплаты сохраняет видимый ключ, копирует его и без Clipboard API и позволяет повторно проверить тот же платёж без создания новой транзакции.
- Стабильная renderer-сборка физически исключает страницы Test Lab, Benchmark, Diagnostics, Licenses и Meeting; они остаются только в Dev.
- Старый лимит накопления HH-вакансий 500 автоматически повышается до 5000, а восстановление очереди больше не обрезается на 1000 записях.

### Fixed
- Release workflow теперь до сборки установщиков проверяет совпадение стабильной версии, тега, верхней записи «Что нового» и CHANGELOG; тег на `-dev` версии останавливается сразу.

## [0.0.37-dev] — 2026-08-19 (dev-сборка с hardening)

### Security
- **JWT-секреты fail-closed:** убраны хардкод-дефолты `dev-access-secret-change-me` / `dev-refresh-secret-change-me` — при отсутствии env-ключей сервер отказывает, а не подписывает подделываемые токены (`apps/api/src/auth/auth.service.ts`).
- **ЮKassa webhook перестал верить телу запроса:** старый `handleYookassaWebhook` теперь перепроверяет платёж через API ЮKassa (`getPayment`) и активирует подписку только для реально оплаченных (`paid === true && status === 'succeeded'`); заглушка `verifyWebhookIp` задокументирована как устаревшая (`apps/api/src/billing/*`).
- **HH OAuth-токены и клиентский секрет шифруются** через Electron `safeStorage`; старый незашифрованный `hh-oauth.json` прозрачно мигрируется при следующем сохранении (`apps/desktop/electron/hhOAuthService.ts`).
- **Path traversal guard** в voice-tests и STT-бенчмарке: аудиофайлы допускаются только внутри разрешённой тестовой директории.

### Changed
- Синхронный `httpx.Client` для claim trial-ключа заменён на `httpx.AsyncClient` — устранена блокировка event loop (фризы всех запросов на ~8 с при холодном кэше).
- SQLite переведён в WAL-режим + `busy_timeout` — устранён класс ошибок `database is locked` при конкурентных STT-stream и HTTP-запросах.
- Устранена утечка дублирующей SQLAlchemy-сессии в `/chat/interview/stream`.
- `datetime.utcnow()` заменён на timezone-aware вариант — совместимость с Python 3.13+.
- Убрана мёртвая зависимость `keytar` из десктопного пакета и `pnpm-workspace.yaml`; `SECURITY.md` приведён к реальной картине (LLM-ключи — в Python `keyring`, HH-токены — в `safeStorage`).

### Fixed
- Уточнены тесты `test_gateway_fallback`, `test_provider_adapter`, `test_tts` под асинхронный `_resolve`/`_gateway_license_key` (336 пройдено).

## [0.0.34] — 2026-08-15

### Added
- Для каждого вопроса работодателя создаётся непустой черновик даже при ошибке провайдера, исчерпанном локальном лимите или временной недоступности выбранного резюме.
- Добавлена миграция старых ответов и выбора резюме: неподтверждённые личные сведения очищаются, а при нескольких резюме приложение просит один раз явно выбрать нужное.

### Changed
- Город проживания и финансовые ожидания определяются по точному резюме выбранной вакансии; содержимое резюме обновляется по времени и при ручном обновлении списка HH.
- Сохранённые ответы по зарплате и городу больше не переносятся между вакансиями как подтверждённые; точный ответ пользователя для конкретной вакансии остаётся приоритетным.
- Свободная генерация в чатах HR разрешена только для объективных технических вопросов; вопросы о личном опыте, мотивации, условиях и документах требуют подтверждения.

### Fixed
- Исправлено смешивание похожих резюме с разными ожиданиями по зарплате, включая варианты `220 000 ₽` и `240 000 ₽`, а также тихая замена удалённого или переименованного резюме.
- Формулировки «Где живёте?» и «финансовые ожидания» теперь распознаются и заполняются из выбранного резюме; регион, место рождения, исторический доход, другая валюта или период не принимаются за эти факты.
- Неподтверждённые варианты `Да/Нет` для личных и юридических вопросов больше не восстанавливаются из старых черновиков и не отправляются автоматически.

## [0.0.33] — 2026-08-15

### Added
- Добавлена серверная проверка источника для ответов на анкеты работодателей: личный факт разрешено отправлять автоматически только при точном подтверждении в резюме, легенде или сохранённом ответе; общие профессиональные вопросы по-прежнему может закрывать ИИ.
- Добавлена проверка основного стека выбранного резюме и вакансии до постановки в очередь, отправки отклика и подготовки сопроводительного письма.
- В карточках незавершённых откликов появилась прямая кнопка перехода к вопросам конкретной вакансии.

### Changed
- Одинаковые вопросы передаются ИИ один раз с ограниченной параллельностью; подтверждённые ответы повторно используются в других вакансиях, а неподтверждённые предложения остаются отдельными черновиками до явного действия пользователя.
- Главная и раздел откликов отдельно показывают вакансии, готовые к запуску, временно отложенные до ежедневного прогона и требующие ручной проверки.
- Ожидания по зарплате распознаются из выбранного HH-резюме, включая формулировки «финансовые ожидания».

### Fixed
- Временный сбой ИИ или загрузки резюме больше не превращается в пачку ложных «вопросов работодателя», не запускает бесконечные повторы и не останавливает обработку остальных вакансий.
- Точные дубли вакансий одного работодателя объединяются, а несовместимые Java, JavaScript/TypeScript, C#, Swift, 1С, Go и другие основные стеки не проходят за счёт вторичных совпадений вроде API, Docker или CI.
- Положительный ответ о переезде больше не переносится на другой город; город, занятость, воинский статус, юридические и другие личные условия не угадываются ИИ.
- Экран вопросов сохраняет черновики и не сообщает об успехе, пока HH фактически не принял ответы; устаревшие счётчики, причины и русские формы слов исправлены.

## [0.0.32] — 2026-08-13

### Changed
- После оценки тренировочного ответа всегда показывается готовый сильный вариант, включая локальный резервный разбор; ответы на широкие технические вопросы раскрывают базовые понятия, практическое применение и важные ограничения в двух коротких абзацах.
- Примеры по Docker объясняют image, container, Dockerfile, registry, Compose и применение в CI, а пример по flaky UI-тестам даёт последовательную диагностику, исправление, карантин и критерий возврата теста.

### Fixed
- Приватная Windows Dev-сборка больше не блокирует AI-разбор коммерческим месячным лимитом владельца; стабильная пользовательская сборка продолжает соблюдать тарифную квоту.

## [0.0.31] — 2026-08-12

### Changed
- Вопросы работодателей вынесены в явное действие «Открыть все вопросы», которое визуально не смешивается с остановкой активного поиска.
- Сводка считает вакансии, действительно требующие решения, и учитывает локально сохранённые ответы в числе оставшихся вопросов.
- После отправки заполненной анкеты автоматически открывается следующая вакансия, а экран вопросов стал компактнее.

## [0.0.26] — 2026-08-12

### Added
- В «Подготовке» можно выбрать резюме прямо из подключённого HH, локальный документ или ручной текст; выбранный источник запоминается. Ссылка на вакансию HH распознаётся автоматически, полное описание загружается без вкладок и отклика, а AI-разбор строится по связке «вакансия + выбранное резюме».
- Во вкладке «Отклики» можно вставить прямую ссылку HH: вакансия добавляется вне зависимости от позиции в поисковой выдаче, проверяется AI и запускается в отклик; журнал запусков хранит время, источник, найденные, проверенные, отправленные и требующие внимания вакансии.
- Добавлен полностью отдельный `SkillCue Dev`: собственные Windows App ID, установщик, профиль данных, локальный backend-порт, keyring, deep link и горячие клавиши позволяют держать Dev и стабильную версию на одном компьютере.
- Ручной GitHub Actions workflow собирает приватный Dev-установщик как временный CI-артефакт без публикации пользователям.

### Changed
- Разовый поиск и ежедневное расписание автооткликов разделены: основная кнопка всегда запускает прогон немедленно, а расписание включается отдельно и показывает точную дату следующего запуска. HH-поиск просматривает до пяти страниц и до ста вакансий вместо узкого окна первых результатов.
- Публичное обновление теперь может запускаться только стабильным git-тегом; ручной запуск release workflow больше не способен случайно заменить установщик по публичной ссылке.
- Редактор доступности для собеседований использует понятные интервалы с шагом 15 минут, включение дней одним нажатием и копирование расписания на будни или всю неделю; лишняя настройка расчётной длительности созвона удалена.
- Разбор собеседования вынесен на отдельную страницу и строится по конкретным парам «вопрос интервьюера → фактический ответ пользователя» с оценкой, ошибками, пробелами и улучшенным вариантом ответа.
- «Личный прогресс» теперь хранит подтверждения из реальных ответов: вопрос, ответ пользователя, тему, оценку и ближайшую зону роста с переходом к полному разбору.

### Fixed
- После запуска поиска основная кнопка показывает реальный этап работы: запуск, поиск вакансий или проверку и отправку откликов, вместо повторного предложения «Запустить поиск сейчас».
- Одна вакансия, для которой не удалось автоматически подготовить письмо или ответы, больше не останавливает всю очередь; выбранное на HH резюме используется для AI-письма и вопросов даже в отдельном Dev-профиле без загруженной локальной копии резюме.
- Обязательный шаг 2 «Что искать» на экране автооткликов больше не схлопывается на невысоком окне; подсказка запуска прокручивает к запросу, фокусирует и подсвечивает незаполненное поле.
- Live-помощник больше не отвечает автоматически после распознавания речи: генерация ждёт явного `Ctrl+Enter`, а обычный Enter в поле ввода только переносит строку.
- Сгенерированные во время созвона подсказки больше не показываются как ответы кандидата и не участвуют в оценке навыков; старый однострочный AI-разбор пересобирается в новый доказательный формат.
- Повторное открытие скрытого оверлея начинает чистую тренировку вместо показа прошлого разбора; активный незавершённый созвон при этом продолжает работать.
- Запуск автооткликов HH больше не выглядит необъяснимо недоступным: экран явно показывает недостающий шаг, клик прокручивает к нему, а единственное резюме выбирается автоматически.
- Во время протягивания диапазона календарь больше не показывает поверх правильного интервала лишнее время ячейки под курсором (`+ 11:30` рядом с `10:30–12:00`).
- Собеседование теперь связано с одной карточкой календаря и одной live-сессией: повторный запуск оверлея не создаёт новую ветку, а после HR- или технического этапа в этой же карточке сохраняются факты, условия, следующие шаги и открытые вопросы.
- Запланированный или прошедший созвон можно удалить из карточки и окна редактирования через нормальное подтверждение внутри приложения; прошедшие встречи больше не исчезают из доступной для управления части календаря.
- Быстрые live-подсказки больше не передают OpenRouter-only параметр `provider` в OpenAI-совместимый gateway; уже установленные версии также защищены серверной фильтрацией, а несовместимые параметры больше не показывают сырой JSON ошибки.
- Подсказка «Что на экране?» больше не упирается в серверный лимит `413`: gateway принимает ограниченный JSON для vision, а клиент заранее сжимает скриншот. Временный `500` распознавания речи повторяется автоматически и больше не выключает активный микрофон после одного неудачного фрагмента.
- Чистая установка теперь сразу открывает главный экран: обязательный онбординг, его вступительные слайды, проверка микрофона и ввод AI-ключа удалены; микрофон и ключи по-прежнему можно настроить позже в обычных «Настройках».
- Недельный календарь стал интерактивной временной сеткой `08:00–18:00`: свободный получасовой слот подсвечивается при наведении, а протягивание по нескольким ячейкам выбирает начало и окончание собеседования без внутренней вертикальной прокрутки.
- Увеличены иконки, заголовки и пояснения в блоке «Что уже готово» на главной странице; вторичный текст стал контрастнее и больше не требует всматриваться.
- Часовой пояс показывается как смещение UTC и город (`UTC+7 · Красноярск`), а верхняя панель страницы «Личный прогресс» больше не подписывается как «Подготовка».
- При первом открытии «Личного прогресса» SkillCue больше не назначает пользователю `QA Automation · Python` по умолчанию: специализация остаётся невыбранной до явного выбора.
- Добровольную настройку профиля и блок «Когда вам удобно» теперь можно свернуть в любой момент; после сохранения обе панели закрываются автоматически.

## [0.0.25] — 2026-08-06

### Added
- **Календарь собеседований:** отдельный недельный экран показывает компанию, вакансию, HR/технический этап, статус подтверждения и ссылку на созвон.
- Можно задать несколько удобных интервалов на каждый день, длительность встречи и минимальный запас до неё, а также вручную добавлять и исправлять события.
- Бот HH распознаёт даты и время в переписке, проверяет пересечения и автоматически предлагает работодателю три ближайших свободных варианта.

### Changed
- Автоответы HR включаются после настройки доступности. При неоднозначной дате бот ничего не выдумывает и переносит диалог в список требующих внимания.
- Принятый слот сначала отмечается как предварительный, после ответа работодателя — как подтверждённый; отмены сохраняются в истории календаря.
- Проверка каждого ответа и автозаполнение вопросов работодателя в вакансии переведены с GPT-5.6 Sol на быстрый gpt-4o-mini и ограничены пятью секундами; подробный итоговый отчёт остаётся отдельным качественным этапом.

- Сопроводительное письмо для HH теперь создаётся отдельно под каждую вакансию: модель сопоставляет полное описание с резюме и легендой, выбирает подтверждённые совпадения и останавливает отклик вместо отправки слабого шаблона.
